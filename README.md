# 기본 유닛 20종 · GitHub Pages 자동 배포 (v0.22.0)

별도 **블루 아카이브 20인 테스트** 시작 항목을 제거하고, 기존 18종을 새 20종으로 교체했습니다. **혼자 연습하기**와 **봇 5명과 연습**, 서버용 사람 대전이 같은 기본 유닛 목록을 사용합니다. 일반 시작은 기존처럼 **1레벨·10골드·빈 전장/대기석**이며 상점에서 유닛을 구매합니다. 캐릭터의 능력치·개별 자동 스킬·20종 그림은 기존 20인 테스트 데이터를 그대로 사용합니다.

기존 18종의 정의와 SVG는 제거했습니다. 상점·봇·공유 풀은 20종 전체를 사용하고, 보상의 기존 레어도 확률(유닛 보상 1~3등급)은 유지합니다. 수호 5종·정찰 8종·비전 7종이며 조합의 기존 2/4/6 기준은 유지합니다. 이전 버전의 연습 저장은 유닛 교체 후 새 경기로 시작합니다.

## 자동 갱신

저장소 **Settings → Pages → Source**를 **GitHub Actions**로 설정합니다. 이후 `main` 브랜치에 소스 변경을 **커밋·푸시**하면 `.github/workflows/pages.yml`이 테스트 → Pages 빌드 → 배포를 실행합니다. 로컬 파일 저장만으로는 배포되지 않습니다. GitHub의 `github-pages` 환경에 배포 브랜치 보호 규칙이 있다면 **Settings → Environments → github-pages → Deployment branches and tags**에서 `main`을 허용해야 합니다. 기존 허용 브랜치와 다른 보호 규칙은 유지합니다. 문서만 바뀐 푸시는 게임 빌드에서 제외합니다. 배포 결과는 저장소 Actions에서 확인합니다.

Pages 주소는 `https://hakka0.github.io/test_ai/`입니다. 배포된 소스 커밋은 `source-version.json`으로 확인합니다. 기존 **Deploy from a branch / gh-pages** 설정을 사용하는 동안에는 `npm run publish:pages`로 수동 갱신할 수 있습니다. 아래 v0.21.2 설명의 브랜치 활성화 방법은 이 수동 방식에 해당합니다.

검증용 전체 배치를 보려면 경기 안의 **정보 → 개발 디버깅 → 기본 20종 배치 확인**을 사용합니다. 일반 시작 메뉴와 별개인 개발 프리셋입니다. 개발·검증 명령은 `npm test`, `npm run test:network`, `npm run build:pages`, `CHROME_PATH=/usr/bin/chromium npm run test:pages:browser`입니다.

# GitHub Pages 1인 연습 (v0.21.2)

휴대폰 브라우저에서 별도 게임 서버 없이 **혼자 연습하기**, **봇 5명과 연습**, **블루 아카이브 20인 테스트**를 플레이할 수 있습니다. Pages 버전에는 친구 방 만들기·참가와 공유 방 코드가 표시되지 않습니다. 기존 Node.js 서버용 실행은 유지합니다.

게임 규칙·상점·전투·보상은 서버와 같은 공통 엔진을 사용합니다. 새로고침하면 같은 탭의 경기를 이어가며, 앱 전환 중에는 진행을 멈춥니다. 로비로 나가면 저장한 경기가 지워집니다. 저장은 현재 탭의 브라우저 저장소를 사용하며 브라우저 데이터 삭제·저장 공간 제한 시 유지되지 않을 수 있습니다. 처음 페이지와 이미지를 읽는 데는 인터넷 연결이 필요합니다.

## Pages 활성화

배포용 파일은 `gh-pages` 브랜치에 저장합니다. 저장소 **Settings → Pages → Build and deployment**에서 **Source: Deploy from a branch**, **Branch: gh-pages**, **Folder: / (root)**를 선택하고 저장합니다. GitHub의 배포 완료 후 저장소 Pages 주소로 접속합니다. 이 저장소의 기본 주소는 `https://hakka0.github.io/test_ai/`입니다. Pages 사용 가능 여부는 저장소 공개 범위와 GitHub 요금제에 따릅니다.

## 개발·배포

- `npm ci` 후 `npm run build:pages`: `/test_ai/` 경로용 로컬 연습판을 `dist-pages/`에 생성합니다. 다른 저장소/도메인 경로는 빌드할 때 `PAGES_BASE_PATH`로 지정합니다.
- `CHROME_PATH=/usr/bin/chromium npm run test:pages:browser`: 게임 백엔드 없이 정적 파일만 제공하여 PC·모바일을 검증합니다. 다른 환경에서는 `CHROME_PATH`를 해당 Chromium 경로로 지정하거나 `npm run setup:browser`를 먼저 실행합니다.
- 소스 변경을 커밋·푸시한 다음 `npm run publish:pages`: Pages 빌드를 생성하고 `gh-pages`를 일반 push로 갱신합니다. 기존 배포 브랜치가 있으면 그 커밋 위에 추가하며 강제 push를 사용하지 않습니다. `source-version.json`에 배포 소스 커밋을 기록합니다. 이 명령은 Pages 설정 자체를 활성화하지 않습니다.
- `npm run build`, `npm start`, `npm run dev`: 기존 서버용 실행입니다. Pages 산출물과 서버용 산출물은 별도 디렉터리에 보관합니다.

검증 범위는 [VALIDATION.md](docs/VALIDATION.md)와 [SCREEN_QA.md](docs/SCREEN_QA.md)를 참고하세요.

# 블루 아카이브 20인 테스트 (v0.21.1)

새 폴더에 배포 ZIP을 풀고 Node.js 22 이상에서 `START-WINDOWS.cmd`를 실행합니다. macOS·Linux에서는 `npm ci` 후 `npm start`를 실행합니다. 브라우저에서 [게임 화면](http://localhost:2567)을 열고 **블루 아카이브 20인 테스트**를 선택합니다.

레벨 10과 30골드, 전장 8명과 대기석 12명으로 시작합니다. 원하는 유닛을 최대 10명까지 출전시키고 **준비 완료**를 누르면 연습 상대와 자동 전투를 시작합니다. 상점과 유닛 보상은 이 모드의 20명 중에서 선택됩니다. 일반 연습·2인 대전·봇 5명 PvP 연습은 기존 18명 카탈로그를 사용합니다.

캐릭터별 능력치와 자동 스킬은 [shared/blue-archive.ts](shared/blue-archive.ts)에 있습니다. 제공받은 20명의 기본 체력·공격력·사거리·공격 및 이동 주기·스킬을 적용했습니다. 기존 전투 엔진용 방어력과 공격·방어 속성은 수호·정찰·비전별로 지정했습니다. 무기 위력과 치명타는 공통 기본값을 적용합니다.

전장에서는 캐릭터별 **384×256 투명 PNG 한 장**의 128×128 프레임 6개를 사용합니다. 각 줄은 왼쪽 대각선, 정면 또는 정후면, 오른쪽 대각선 순서입니다. 윗줄은 앞모습, 아랫줄은 뒷모습입니다. 상점·대기석·유닛 상세에는 정면 PNG를 표시합니다. [화면 안내](docs/MAIN_INTERFACE.md) · [검증](docs/VALIDATION.md)

## 분리된 준비/경험치 버튼과 장비 드래그 (0.17.0)

하단 고정 창을 **상점 / 대기석** 두 탭으로 정리하고 같은 높이를 사용하도록 바꿨습니다. **경험치 구매는 왼쪽 위**, **준비 완료는 오른쪽 위**에서 창 바깥으로 돌출되며, 두 버튼은 모든 탭과 접힌 상태에서 유지됩니다. 버튼 사이를 넓게 떨어뜨리고 드래그에서 발생한 호환 클릭으로 준비/경험치/리롤이 실행되지 않도록 차단합니다.

보유 장비와 조합 재료는 **왼쪽 별도 패널**로 옮겼습니다. PC에서는 전장 왼쪽에 표시하며 모바일/좁은 PC 창에서는 왼쪽 장비 버튼으로 펼칩니다. 장비를 **전장 또는 대기석의 내 유닛에 직접 드래그**하면 장착됩니다. 드래그 중 대상 이름·강화 등급·장비 수/한도와 초록색/빨간색 강조를 표시합니다. 장착을 위해 별도 장비 팝업을 열 필요가 없습니다. 키보드/터치 대안은 장비 선택 → 받을 유닛 클릭입니다.

- 상대 유닛·빈 칸·장비 한도 초과·조합 재료·준비 완료 후·전투 중 장착을 거절합니다. 취소/Escape/회전/창 크기 변경/연결 해제/모달 열기에서는 드래그를 취소합니다. 장착 시 기존 서버의 권한과 거래 처리를 사용합니다.

## 유닛 자동 합성 (0.6.0)

- 같은 종류·같은 강화 등급 3개를 획득하면 자동 합성합니다. 강화 1성 3개→2성, 2성 3개→3성, 최대 3성입니다. 전장과 대기석의 본인 유닛을 함께 검사합니다.
- 레어도 1~5성은 기본 가격이며 강화 1~3성은 개별 유닛의 능력치입니다. 상점·대기석·전장·상세 창에서 구분합니다.
- 판매가는 레어도 기본 가격 × 원본 수입니다. 강화 1/2/3성은 각각 기본 가격의 1/3/9배로 판매합니다. 예: 레어도 2인 실바의 강화 2성은 6골드입니다. 리롤은 5골드입니다.
- 기본 체력·공격력만 등급당 1.8배로 성장합니다(최종 반올림). 장비의 고정 보너스는 이후 한 번 가산합니다. 스킬의 고정 피해·회복·보호막 수치, 공격 속도·사거리·이동 속도는 그대로입니다. 스킬의 공격력 비례 효과는 강화 공격력을 사용합니다.
- 전장 유닛을 우선 남겨 ID와 위치를 유지합니다. 장비는 남는 유닛의 장비 우선으로 2개까지 이관하고 초과분은 인벤토리에 반환합니다. 합성으로 비는 출전 자리는 직접 채워야 합니다.
- 대기석이 가득 차도 즉시 합성할 수 있으면 구매합니다. 그 외 만석 구매는 골드·상품·ID를 바꾸지 않고 거부합니다.
- 연습 상대도 동일한 합성·판매 규칙을 사용합니다. 상대에게는 전장 유닛의 강화 등급만 공개하며 합성 내역·대기석은 숨깁니다.
- `npm run dev:debug` → 혼자 연습하기 → 개발 디버깅 → **합성 · 기사 2개** → 시작 상태 적용. 상점 첫 칸을 구매하면 전장 기사가 2성으로 강화됩니다. 저장/복원으로 같은 획득·장비 상태를 반복할 수 있습니다.

빌드 및 규칙 테스트 69개·실제 서버 통신 3개가 통과했습니다. 강화 후 통신·장비·저장 복원·재접속·판매도 확인했습니다. 브라우저 테스트에 합성 표시와 판매 검사를 추가했으나 Chromium이 없어 실행하지 않았습니다. 실제 휴대폰 검사와 온라인 테스트 사이트 배포도 미실행입니다.

합성 도입 후 기존 고정 시드 성장 투자 진단 3개는 26~27라운드, 약 19.1~20.0분, 종료 9레벨입니다. 25~35분 목표보다 짧으며 패배 피해·강화 능력치·구매 전략의 밸런스 재조정이 남아 있습니다. 아래 0.5.0의 25.7~25.9분 수치는 합성 도입 전 결과입니다. 실제 이용자 평균을 의미하지 않습니다. 상세 규칙은 `docs/GAME_RULES.md`를 보세요.

## 장기 경기와 디버깅 (0.5.0)

TFT 일반 모드의 경제·성장 구조를 참고해 2인 경기를 늘렸습니다. 3승 선취 대신 체력 100에서 시작하여 체력 0이면 탈락합니다. 최대 40라운드이며 체력이 같으면 승수, 둘 다 같거나 모두 체력 0이면 무승부입니다. 스테이지는 6라운드씩 묶으며 2-1부터 시작합니다. PvE·공동 선택 라운드는 없습니다.

- 기본 수입 5골드 + 이자(잔액 10골드당 1, 최대 5) + 연승/연패 수입(2~3회 1, 4회 2, 5회 이상 3).
- 승리 보너스 1골드는 전투 종료 시 즉시 지급합니다. 이자는 전투 시작 잔액 기준이며, 기본·이자·연속 수입은 다음 준비 단계에서 지급합니다. 무승부는 연속 기록을 초기화합니다.
- 경험치는 다음 라운드 +2, 구매는 4골드로 +4입니다. 필요량은 2/2/6/10/20/36/56/68/68입니다. 첫 구매로 1→3레벨이 됩니다.

## 현재 상점 규칙

- 플레이어마다 랜덤 상품 5칸이 항상 표시됩니다. 현재 6종 유닛을 같은 확률로 뽑으며 중복이 가능합니다. 리롤 후 같은 종류가 다시 나올 수도 있습니다.
- 시작 골드 10 G, 구매·강화 1성 판매는 레어도 1~5성과 같은 가격이며 강화 2/3성 판매는 기본 가격의 3/9배입니다. 리롤은 5 G입니다. 2라운드부터 기본 5 G + 이자·연속 수입을 지급합니다.
- 상품을 터치하면 대기석에 유닛이 추가되고 해당 상품 칸을 구매 완료로 비웁니다. Reroll은 5칸을 모두 다시 뽑습니다.
- 상점 거래는 준비 완료 전 또는 전투 중에 가능합니다. 전투 중 구매·합성은 다음 전투부터 반영되며 배치는 변경할 수 없습니다. 골드 부족 시 버튼이 비활성화됩니다.
- 상품·골드·구매·리롤을 서버에서 판정하며, 이전 상점 버전의 중복 요청을 거부합니다. 재접속 시 그대로 복원합니다.
- 다음 라운드에 상품은 유지됩니다. 판매·자동 합성을 지원합니다. 공유 유닛 풀·레벨별 확률은 아직 없습니다. 연습 상대는 실제 수입으로 레벨과 유닛 수를 늘립니다.
- 가격·골드·상품 수는 `shared/shop.ts`, 종류·레어도·추첨 대상은 `shared/catalog.ts`에서 수정하세요. 구매한 유닛은 기존 배치·스킬·장비 시스템을 사용합니다.
- 전체 클라이언트와 서버를 함께 업데이트하세요. 반영된 빌드도 포함되어 있습니다.

```powershell
npm.cmd start
```

`npm.cmd`는 PowerShell의 npm.ps1 실행 정책 문제를 피하기 위해 사용합니다. 이 프로젝트는 유료 API 키나 ChatGPT API를 사용하지 않습니다.

## 개발하면서 수정하기

```powershell
npm.cmd run dev
```

- 화면: http://localhost:5173 — 수정 시 자동 갱신
- 게임 서버: http://localhost:2567 — 서버 파일 변경 시 재시작
- 서버 재시작 시 메모리에 있던 방과 경기는 사라집니다.
- `npm.cmd run build`는 파일 생성만 합니다. `npm.cmd start`는 서버 실행입니다.
- 처음부터 만들어진 `dist`도 ZIP에 포함했습니다. 수정 후에는 다시 빌드하세요.

## 휴대폰에서 테스트

1. PC와 휴대폰을 같은 Wi-Fi에 연결합니다.
2. PC에서 `ipconfig`를 실행하고 Wi-Fi/Ethernet의 IPv4 주소를 확인합니다. 예: `192.168.0.10`.
3. 위 실행 방법으로 PC 서버를 켭니다.
4. 휴대폰 브라우저에서 `http://192.168.0.10:2567` 에 접속합니다.
5. Windows 방화벽이 물으면 사용 중인 **개인 네트워크**에서 Node.js 접근을 허용합니다.
6. 안 되면 PC와 휴대폰이 같은 네트워크인지, 게스트 Wi-Fi가 장치 간 통신을 차단하는지 확인합니다.

휴대폰의 `localhost`는 PC가 아니라 휴대폰 자신입니다. 반드시 PC의 IPv4 주소를 사용하세요. 개발 모드라면 `:5173` 으로 접속하며 게임 연결에는 `:2567`도 필요합니다. 기본 실행 모드는 `:2567` 하나만 사용합니다.

화면 회전 잠금을 해제하면 세로/가로 양쪽을 사용할 수 있습니다. 세로가 기본 레이아웃이며 가로에서 정보 패널이 오른쪽으로 이동합니다. 좁거나 짧은 화면은 세로 스크롤이 있을 수 있지만 전장 자체에 가로 스크롤은 없습니다. 실제 Android/iOS 장치 검증은 별도로 진행해야 합니다.

## 두 명이 대전하기

- 첫 번째 사람이 `친구와 대전 · 방 만들기`를 누릅니다.
- 화면 상단의 **4자리 방 코드**를 두 번째 사람에게 전달합니다.
- 두 번째 사람은 같은 서버 주소에 접속하고 코드를 입력한 뒤 `참가`를 누릅니다.
- PC 브라우저 두 개의 탭으로도 테스트할 수 있습니다. 참가자는 탭 단위로 구분합니다.
- 상대가 입장하면 준비 30초가 시작됩니다. 양쪽 준비가 완료되면 즉시 전투합니다.
- 인터넷상의 다른 네트워크에서 플레이하려면 공용 서버와 HTTPS/WSS 설정이 필요합니다. 이 ZIP은 외부 서버에 배포되어 있지 않습니다.

## 조작과 규칙

- 기사 1명은 전장, 궁수·마법사는 대기석에서 시작합니다.
- 아래 캐릭터 버튼을 선택한 뒤 **아래쪽 4행**의 빈 칸을 누릅니다.
- 전장의 내 캐릭터를 직접 선택하거나 드래그해서 옮길 수도 있습니다.
- `대기석으로` 버튼 또는 전장에서 대기석 영역으로 드래그해 배치를 해제합니다.
- 아군은 초록 테두리/화면 아래, 적군은 분홍 테두리/화면 위입니다. 색상 외 위치·안내 문구도 제공합니다.
- 유닛 선택 후 `장비` 버튼으로 바로 장착·해제·이동할 수 있습니다. 오른쪽/아래 `장비 관리`도 사용할 수 있습니다. 캐릭터당 2개입니다.
- 준비 완료 후에는 배치와 장비를 변경할 수 없습니다.
- 전장에 둔 캐릭터만 싸웁니다. 빈 전장은 패배, 양쪽 빈 전장은 무승부입니다. 무승부에서도 양쪽 체력이 줄어듭니다.
- 맨해튼 거리로 사거리와 경로를 판정하며 가까운 적을 공격합니다. 장애물/다른 캐릭터를 피하는 격자 경로 탐색을 사용합니다.
- 전투 제한 40초, 결과 표시 6초. 체력 100에서 시작하며 0이면 탈락합니다. 최대 40라운드에서는 체력, 승수 순으로 승자를 정합니다.
- 회전과 화면 크기 변경은 서버 상태를 변경하지 않습니다.
- 앱 전환/새로고침/연결 끊김에는 최대 60초 동안 재접속합니다. 그동안 경기는 계속되고, 복귀하면 최신 상태를 받습니다. 브라우저가 탭 저장소를 지웠거나 유예시간이 지났으면 복구할 수 없습니다.
- `로비`를 누르면 명시적으로 경기를 나갑니다. 진행 중 이탈은 패배로 처리합니다.
- `효과 줄이기`는 이동 보간·흔들림·피격 효과를 줄입니다. 운영체제의 동작 줄이기 설정도 최초 적용합니다.
- Tab/Enter로 캐릭터·칸·장비를 조작할 수 있으며 칸과 체력에 접근성 레이블이 있습니다. 전체 스크린리더 사용성 검증을 완료했다는 의미는 아닙니다.

## 이번 버전의 범위

구현: 캐릭터 배치, 6종 자동전투·3계열 시너지, 2인 방 코드, 연습 상대, 서버 시간, 재접속, 세로/가로 UI, 예제 장비 3종, 액티브·패시브 스킬 12종.

후속 작업: 확장 후 경기 길이·조합 수치 재조정, 추가 유닛·조합 단계·장비 성장·전투 결과 개선, 8인 경기, 계정·랭킹·DB, 사운드, 상용 수준 밸런스와 부하 테스트. 연습 상대는 정해진 구매·성장 정책을 사용하며 학습형 AI가 아닙니다. 네트워크 지연으로 화면 표시에는 작은 차이가 있어도 판정은 서버 하나에서 수행합니다.

실서비스 공개 전에는 HTTPS/WSS, 생성 방 수/IP별 요청 제한, 접근 출처 정책, 모니터링, 서버 장애 복구·영속 저장 등을 배포 환경에 맞춰 추가해야 합니다. 현재 방 상태는 메모리에만 있고 실제 시간 90분 후 방을 정리합니다.
