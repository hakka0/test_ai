# 캐릭터·무기·모션·속성 수정 매뉴얼

기준: **autochess-web v0.20.68 / 2026-11-03**

기존 캐릭터를 수정하거나 FPS 캐릭터를 추가할 때 보는 작업 안내서입니다. 코드 편집이 익숙하지 않다면 1~4장부터 순서대로 진행하세요. 6~7장은 현재 기능을 확장하는 개발 작업입니다.

v0.20.68의 패널·카드 마감은 `client/interface-theme.css`에 모았습니다. 기존 배치/반응형 치수는 `client/style.css`와 `client/pc-layout.ts`가 담당합니다. 전장 이미지 슬롯은 칸의 96%이며 원본 비율을 유지합니다(`client/unit-appearance.ts`). 준비 중 캐릭터 프레임과 전장 색은 `client/board.ts`, 대기석의 칸 내부 초상화/이름은 테마 CSS입니다. 새 캐릭터 일러스트/프로필 사진 업로드는 이번 변경에 포함하지 않았습니다.

v0.20.67의 상점 드래그 그림은 전용 `.shop-drag-portrait` 스타일을 사용합니다. 예전 `.shop-portrait`의 화면별 축소 규칙을 복사본에 적용하지 않습니다. 바깥 크기는 원래 상품 카드의 실제 너비/높이이며 `object-fit: contain`으로 그림 비율을 유지합니다. 유닛 상세의 두 스킬은 `[data-skill-cards]`의 2열 그리드로 한 줄에 놓고 아이콘은 32px로 표시합니다. 모양은 `client/style.css`, 복사본 크기 측정은 `client/shop-preview.ts`에서 수정합니다.

v0.20.66부터 상점은 PC 클릭/모바일 터치 즉시 구매, 내 대기석으로 드래그해도 구매합니다. PC 호버 툴팁은 패시브 → 액티브 스킬 이름/효과만 표시합니다. [client/shop-preview.ts](../client/shop-preview.ts)에서 `UNITS[kind].skills`와 `SKILLS`, `skillDescriptionFor`를 사용하므로 캐릭터 스킬을 수정하면 함께 바뀝니다. 효과 수치는 장비/조합 보너스 없는 강화 1성 기준입니다. 별도 상점용 수치는 없습니다. 구매 오버레이와 ⓘ 버튼은 제거했습니다.

합성 직전 상품의 청백색 테두리는 `client/main.ts`의 `mergeReady`에서 내 전장/대기석의 같은 종류 강화 1성 수를 계산해 표시합니다. 카드 크기를 바꾸지 않습니다. 모양은 `client/style.css`의 0.20.66 부분, 드래그 복사본/취소/구매 검증은 `client/shop-preview.ts`입니다. 전투 중 합성 보류와 서버 구매 규칙은 유지합니다. [조작·배치 안내](MAIN_INTERFACE.md).

v0.20.58에서 조합 검사용 12종을 추가해 총 18종, 계열당 6종입니다. 기존 6종의 설정은 유지하고 새 유닛에는 임시 능력치/속성/기존 스킬과 색상·번호가 붙은 500×500 SVG를 배정했습니다. 아래 원본 6종의 예시와 같은 방식으로 수정합니다. [추가 ID 전체 목록·조합 프리셋·이미지 수정 위치](EXPANDED_UNITS.md).

v0.20.53의 중립 미니언은 상점 캐릭터와 별도로 관리합니다. 이미지·능력치·첫 3회 구성·처치 보상·드롭 연출과 연승/연패 금액을 수정할 때는 [미니언 도입부·연속 골드 안내](MINION_ROUNDS.md)를 참고하세요.

문서 안의 파일 경로는 프로젝트 폴더를 기준으로 합니다. 파일의 줄 번호는 변경될 수 있으므로 **파일을 열고 안내된 이름을 검색**하세요. 아래 예시는 별도 표시가 없으면 TypeScript 코드입니다.

## 2. 실행하고 수정 결과 확인하기

### 2-1. 작업 준비

1. 원본 프로젝트 또는 수정할 파일을 별도 폴더에 복사해 보관합니다.
2. 코드 편집기로 프로젝트 폴더를 엽니다. 폴더 안에 `package.json`이 있어야 합니다.
3. 프로젝트 폴더에서 PowerShell 터미널을 엽니다.
4. 처음 실행하거나 의존성을 다시 설치해야 할 때만 다음 명령을 실행합니다. `package.json`의 Node.js 요구 버전은 22 이상입니다.

```powershell
npm.cmd ci
```

### 2-2. 수정하면서 보기

```powershell
npm.cmd run dev
```

브라우저에서 [개발 화면](http://localhost:5173)을 엽니다. 게임 서버는 기본적으로 2567번 포트를 사용합니다. 종료는 터미널에서 **Ctrl+C**입니다.

- `client/` 변경은 대체로 화면 자동 갱신으로 확인할 수 있습니다.
- `shared/`, `server/` 변경은 서버가 재시작될 수 있으며, 진행 중이던 메모리의 방과 경기는 사라질 수 있습니다.
- 캐릭터 능력치·스킬·종류를 바꾼 뒤에는 **새 연습 경기를 시작해서 확인**하세요. 진행 중 전투의 Fighter에는 전투 시작 시 만든 능력치·스킬 상태가 들어 있습니다.
- 개발 화면을 켜 둔 상태에서 별도로 `npm start`까지 실행하면 서버 포트가 겹칠 수 있습니다. 실행 방식은 하나를 선택하세요.

### 2-3. 빌드된 게임으로 보기

개발 서버를 종료한 뒤 실행합니다.

```powershell
npm.cmd start
```

현재 프로젝트의 `prestart`가 타입 검사와 빌드를 먼저 실행합니다. 완료되면 [게임 화면](http://localhost:2567)을 엽니다. `dist/`는 생성 결과이므로 수정은 원본 `client/`, `shared/`, `public/` 파일에 합니다.

### 2-4. 상점 자동 갱신 확인

상점 자동 갱신은 v0.20.40부터 다음 라운드의 준비 진입 시 `shared/engine.ts`의 `prepare()`에서 실행합니다. 라운드 결과 중에는 기존 상품·구매 완료 상태를 유지하며 수동 리롤과 남은 상품 구매가 가능합니다. 최초 준비와 최종 경기 종료에서는 추가 자동 갱신을 하지 않습니다.

## 3. 기존 캐릭터의 이름·능력치·속성 바꾸기

### 3-1. 캐릭터 ID 찾기

[shared/catalog.ts](../shared/catalog.ts)를 열고 `UNITS`를 검색합니다.

| 내부 ID | 현재 이름 |
| --- | --- |
| `knight` | 루멘 |
| `ranger` | 실바 |
| `mage` | 노바 |
| `warden` | 아르덴 |
| `skirmisher` | 카이 |
| `oracle` | 세라 |

화면에 보이는 이름만 바꿀 때는 **`name`만 수정**하세요. `knight` 같은 내부 ID는 캐릭터 종류를 연결하는 키입니다. ID 변경은 새 종류 추가와 관련 참조 수정이 필요한 작업입니다.

### 3-2. 수정 예시

다음은 기존 `knight` 항목을 FPS 캐릭터처럼 바꾸는 예시입니다. 파일 전체를 교체하지 말고 **`UNITS` 안의 `knight` 항목만** 바꿉니다.

```ts
knight: {
  name: "루멘",
  attackAttribute: "red",
  defenseAttribute: "blue",
  rarity: 1,
  trait: "bulwark",
  skills: ["guardian", "lastStand"],
  role: "중장갑 사수",
  image: "/units/knight.svg",
  stats: {
    hp: 300,
    attack: 24,
    defense: 12,
    weaponPower: 10,
    critChance: 10,
    critDamage: 150,
    interval: 900,
    range: 3,
    moveMs: 500,
  },
},
```

이 예시는 이름·능력치 등의 설정을 바꿉니다. 이미지나 무기 모양은 별도로 수정해야 합니다. `role`을 사수로 바꿔도 총기 종류가 자동으로 달라지지는 않습니다.

| 항목 | 의미 | 수정할 때 알아둘 점 |
| --- | --- | --- |
| `name` | 표시 이름 | 한글 사용 가능 |
| `role` | 역할 설명 | 설명문이며 전투 규칙을 직접 바꾸지 않음 |
| `rarity` | 희귀도·기본 구매 가격 | 1~5. 현재 1성 구매 가격과 동일하며 합성 강화 등급 `rank`와 다름 |
| `trait` | 시너지 계열 | 현재 `bulwark`, `scout`, `arcane` |
| `image` | 대표 이미지의 웹 경로 | `public/` 아래 파일을 가리킴. 경로에 `public`을 넣지 않음 |
| `skills` | 스킬 ID 목록 | `skill-catalog.ts`에 등록된 ID 사용 |
| `hp` | 기본 최대 체력 | 실제 전투에는 강화·시너지·장비 보정도 적용됨 |
| `attack` | 기본 공격력 | 스킬의 공격력 계수에도 영향을 줄 수 있음 |
| `defense` | 수치 방어력 | 최소 1. 두 배면 반올림 전 직접 피해 절반. 색상 방어 속성과 별개 |
| `weaponPower` | 무기 위력 | 현재 공통 10. 두 배면 반올림 전 피해 두 배. 총기 종류와 모션은 아직 공통 |
| `critChance` | 치명타 확률(%) | 기본 10. 0~100. `0.1`이 아닌 `10`을 입력해야 10% |
| `critDamage` | 치명타 총 피해(%) | 기본 150. 150%는 총 1.5배. 최소 100 |
| `interval` | 기본 공격 주기, 밀리초 | 1000 = 1초. 작을수록 빠름. 화면은 실제 간격을 초당 공격 횟수로 환산한 공격 속도와 등급을 표시 |
| `range` | 기본 공격 사거리, 칸 | 현재 격자의 맨해튼 거리 기준 |
| `moveMs` | 이동 주기, 밀리초 | 작을수록 자주 이동 |

`statsFor()`는 최대 체력·방어력을 최소 1, 공격력·무기 위력을 최소 0, 치명타 확률을 0~100%, 총 치명타 피해를 최소 100%, 공격·이동 주기를 최소 100ms, 사거리를 최소 1로 보정합니다. 강화는 기본 체력·공격력에만 성급당 1.8배이며 방어력·치명타는 자동 증가하지 않습니다. 수치를 바꿀 때는 장비·시너지·스킬 보정까지 함께 확인하세요.

현재 기본값은 `BASE_COMBAT_STATS`에 있으며 각 유닛의 `stats` 안에서 `...BASE_COMBAT_STATS` 뒤에 `critChance: 20` 등을 추가하면 해당 유닛만 덮어씁니다. [적용한 계산식·전체 수치·밸런스 확인 방법](COMBAT_BALANCE.md)을 확인하세요. 핵심은 `무기 위력 × (고정 피해 + 공격력 × 계수) / 방어력 × 치명타 배율`이며, 스킬의 받는 피해 배율을 곱한 뒤 한 번 반올림합니다. `shared/damage.ts`에 계산식을, `shared/skills.ts`에 배리어·체력 분배를 둡니다.

### 공격 속도 표시 조정

화면은 스톱워치 아이콘 옆에 숫자와 작은 등급을 함께 표시합니다. 이름·단위는 툴팁에서 확인합니다. 별도 공격 속도 데이터를 중복 저장하지 않고 `stats.interval`에서 자동 계산합니다. 변경 위치는 `shared/attack-speed.ts`의 `attackSpeedFor()`와 `attackSpeedGrade()`입니다.

- 실제 전투는 100ms 단위입니다. 850ms 설정은 실제 900ms 간격이므로 1.11회/초, 1150ms는 1200ms 간격이므로 0.83회/초입니다.
- 숫자는 소수점 둘째 자리까지 표시하고 그 숫자로 등급을 정합니다. 0.70 미만 매우 느림, 0.70~0.90 미만 느림, 0.90~1.10 미만 보통, 1.10~1.30 미만 빠름, 1.30 이상 매우 빠름입니다.
- 0.5~1.5로 표시를 제한하지 않습니다. 장비 등으로 2.00이 되면 그 값을 그대로 보여줍니다. 최소 공격 간격 100ms라는 기존 전투 하한은 유지합니다.
- 상세의 기준은 다른 능력치와 같습니다. 준비 중에는 장비·시너지 포함 값, 전투 중 내 유닛은 다음 전투 기준 값입니다. 일시적 전투 버프의 실시간 수치는 이 상세에 추가 전송하지 않습니다.

### 능력치 아이콘과 순서 바꾸기

`client/unit-stats.ts`의 `UNIT_STAT_ICONS` 배열에 표시 순서·한국어 이름·아이콘 색상·SVG 경로·설명문을 둡니다. 현재 순서는 `hp`, `attack`, `defense`, `crit-chance`, `crit-damage`, `attack-speed`, `range`이며 3칸씩 표시합니다. 치명타 2개 아이콘은 같은 `criticalFragment` 모양을 공유하며 피해 아이콘에만 위 화살표를 추가합니다. 작은 화면에서도 선명하도록 SVG를 사용합니다.

`unitStatsMarkup()`이 실제 값·접근성 레이블·툴팁 제목을 연결합니다. 칸 크기와 3열 배치는 `client/style.css`의 0.20.41 주석 부분을 수정합니다. 아이콘이나 색상을 바꿔도 전투 능력치·속성색·피해 계산은 바뀌지 않습니다. PC 도움말은 마우스 호버, 모바일은 탭 전환입니다.

### 강화·레어도 요약과 선택 표시 바꾸기

`client/unit-summary.ts`의 `unitSummaryMarkup()`이 `★★ · ★1 · 1G`를 만듭니다. v0.20.47부터 강화는 `rank`만큼 **파란 별**, 레어도는 **노란 별 옆 `rarity` 숫자**로 표시합니다. 가격은 기본 가격인 `rarity`골드입니다. 요약 문양을 바꿀 때 접근성 이름과 `client/help-tooltips.ts`의 `unit` 설명도 함께 수정하세요. 색은 `client/style.css`의 `.unit-meta`와 0.20.47 부분을 사용합니다. 전장의 파란 강화 별은 `board.ts`의 `ranks` 텍스트, 대기석은 `.pc-bench-rank`입니다. 실제 판매 금액 계산은 별도 `unitSellPrice()`이며 상세 이름 옆과 오른쪽 정보의 판매 버튼에 표시합니다.

### 공유 풀·판매·3성 추첨 제한 바꾸기

`shared/unit-pool.ts`의 `UNIT_POOL_SIZE`(현재 30)가 종류당 공유 원본 수량입니다. `remainingCopies()`는 모든 유저의 전장/대기석, 합성 원본 수(1/3/9), 미구매 상점과 미선택 유닛 보상을 계산합니다. 별도 가변 수량을 저장하지 않으므로 저장/복원도 같은 보유 상태에서 계산합니다. `pickPoolKind()`는 남은 수량으로 가중 추첨하며 `hasMaxRank()`가 본인 3성 종류를 제외합니다. 다른 유저의 같은 종류를 전역 금지하지 않습니다.

`shared/shop.ts`의 `refreshShop()`은 세 번째 인자로 전체 참가자 배열을 받습니다. 실제 서버에서는 반드시 경기의 `m.players`를 전달해야 합니다. `shared/rewards.ts`의 `offerRoundReward()`는 네 번째 인자, `chooseReward()`는 다섯 번째 인자로 같은 배열을 받습니다. 수량 부족 시 후보를 억지로 만들지 않습니다. 본인 3성 완성 후 기존 상품/보상 정리는 `removeMaxRankOffers()`입니다. 서버의 직접 구매·보상 수령·봇 경로도 공유 풀을 검증합니다.

v0.20.50부터 `acquireUnit()`와 `canAcquireUnit()`의 세 번째 인자 `mergeNow`로 즉시 합성 여부를 지정합니다. 기본값은 `true`이며 준비 중 구매·보상·봇이 사용합니다. 서버 구매는 `m.phase === 'prepare'`를 전달하고 클라이언트 상품 활성화도 같은 조건을 사용합니다. 전투·결과에서는 `false`로 각각의 원본을 정상 대기석에 보관하므로 만석 예외 구매를 허용하지 마세요. `prepare()`의 `mergeRoster()`가 상점·보상 생성 전에 모든 종류의 합성을 처리합니다. `mergeAcquiredKind()`는 각 성급에서 가능한 모든 3개 묶음을 반복 처리해 3성까지 연쇄 합성합니다. 전투 `Fighter`를 수정하지 않고 실제 보유 목록으로 보류 상태를 유지하므로 저장·재접속이나 판매에도 별도 예약 목록이 필요하지 않습니다.

판매 드래그는 `client/interaction.ts`의 `shop` 목적지와 `main.ts`의 `dropTarget()`을 사용합니다. 상품 영역 `#pc-dock-reserve`에 들어가면 `#shop-sell-overlay`를 표시합니다. 이름 옆 판매 버튼은 `sellSelected()`, 상세 상단은 `#unit-title-sell`입니다. v0.20.60에서 `canSell(id)`와 공통 `shared/shop.ts`의 `sellActionOpen()`을 사용해 **전투 중 대기석만 판매**하고 준비 완료 전·결과는 기존 전장/대기석 판매를 허용합니다. 전투에서는 보유 유닛의 `x < 0`과 현재 `fighters`의 동일 소유자/ID가 아님을 함께 확인하며, 죽은 출전 유닛도 보호합니다. 전장 배치는 별도 `canEdit()`로 준비 완료 전만 허용합니다. `placementIntent()`의 다섯째 인수는 대상 ID의 판매 권한입니다. 판매 가격은 `unitSellPrice()`, 장비 반환·실제 유닛 제거는 서버 `sell` 분기입니다. 진행 중인 `Fighter`는 삭제하거나 변경하지 마세요. 결과에서 판매한 전투 유닛의 상세는 `client/unit-inspection.ts`에서 `Fighter`로 조회하며 관리 조작은 숨깁니다. 중앙 편성 수는 `client/main.ts`가 전투 중 `#deployment-overlay`를 숨기며 CSS의 `[hidden]` 규칙도 유지해야 합니다.

준비·전투 관전의 양쪽 참가자는 `client/scouting.ts`의 `battleBoard()`와 `scoutingBoard()`가 `Snapshot.battlePairs` 순서로 선택합니다. 순위 정렬 순서와 무관하게 이 순서를 유지해야 `board-geometry.ts`의 좌표 반전이 맞습니다. 준비는 현재 `units`, 전투는 고정 `fighters`를 사용하며 미매칭 유저는 본인 배치만 표시합니다.

v0.20.49부터 `Match.mode`가 PvP(`duel`)·PvE(`practice`)를 구분합니다. PvP 준비 종료는 `finishPreparation()` → `matching` → `startCombat()` 순서이며 매칭 시간은 `shared/model.ts`의 `MATCHING_MS`(5000ms)입니다. PvE는 즉시 전투로 이동합니다. 타이밍을 바꾸면 `tick()`·`advanceMatch()`와 화면의 단계/타이머도 확인하세요. `snapshotFor()`는 PvP 준비/매칭에서 상대 `units`·`bench`·`inventory`·`fighters`·`events`·대전 쌍을 비우고 `rosterVisible:false`를 전송합니다. 화면에서만 숨기는 방식으로 바꾸지 마세요.

관전 중 구매는 `main.ts`의 `canPurchase()`로 별도 허용합니다. `canShop()`은 관전 중 리롤/경험치/장비/판매 제한을 유지하므로 둘을 합치지 마세요. 구매와 합성은 항상 접속자 본인의 보유 목록을 수정하며, 관전 유닛 선택을 합성 결과로 옮기지 않습니다. 방 코드의 4자리 형식과 중복 예약/반환은 `server/room-code.ts`, 표시/입력은 `client/main.ts`·`room-code-ui.ts`에서 변경합니다.

전장의 노란 삼각형과 칸 윤곽선은 `client/board.ts`의 `drawSelection()`에서 그립니다. 삼각형은 실제 이미지의 상단과 체력/자원 바를 기준으로 배치하므로 500×500 이미지로 교체해도 크기를 따라갑니다. 색은 `0xffd84a`, 삼각형 폭·높이·부유량·윤곽선 굵기를 이 함수에서 조절합니다. 효과 줄이기에서는 정지 상태를 유지해야 합니다. 대기석의 같은 색은 `client/style.css`의 0.20.43 부분과 `client/main.ts`의 `.bench-selection-pointer` SVG에 연결됩니다. 전장과 대기석의 표시를 함께 확인하세요. 검사 명령: `npm run test:unit-selection:browser`.

### 3-3. 속성 배정 바꾸기

캐릭터 항목의 두 값을 각각 고릅니다.

```ts
attackAttribute: "purple",
defenseAttribute: "yellow",
```

사용 가능한 ID는 `red`, `yellow`, `blue`, `purple`입니다. 문자열은 영문 소문자로 입력합니다.

| 화면 요소 | 따르는 색상 |
| --- | --- |
| 총구 섬광·탄도·스킬 발동 및 유지 표시 | 시전자의 공격 속성색 |
| 일반 체력 피해 숫자 | 공격자의 공격 속성색 |
| 몸체 피격 효과·배리어 생성/피격/파괴·회복 표시 | 대상의 방어 속성색 |
| 배리어가 흡수한 피해 숫자 | 고정 연한 파란색 `#b8eaff` |
| 아군·적군의 체력바와 기본 진영 표시 | 진영 구분 색상. 속성과 별개 |

예를 들어 빨강 공격자가 배리어 30인 적에게 100 피해를 주면, **연한 파란 `−30`과 빨강 `−70`**을 표시합니다. 배리어 자체의 파문과 파편은 적의 방어 속성색입니다.

### 3-4. 속성 색상표 자체 바꾸기

[shared/combat-attributes.ts](../shared/combat-attributes.ts)의 `COMBAT_ATTRIBUTES`를 수정합니다.

```ts
red: { name: "빨강", color: 0xff667a, css: "#ff667a" },
```

- `name`: 화면에 표시할 속성 이름입니다.
- `color`: Phaser 그림에 사용하는 숫자 색상입니다.
- `css`: 글자·HTML 표시 등에 사용하는 문자열 색상입니다.
- 같은 속성의 색상을 바꿀 때는 **`color`와 `css`를 같은 RGB 값으로 함께 수정**합니다.
- 이 변경은 해당 속성을 쓰는 모든 캐릭터에 적용됩니다.

현재 값은 빨강 `#ff667a`, 노랑 `#ffd45c`, 파랑 `#66baff`, 보라 `#c58aff`입니다. 배리어 피해 숫자의 고정색은 `client/combat-effects.ts`의 `BARRIER_DAMAGE_COLOR`에서 따로 관리합니다.

## 4. 캐릭터 이미지 교체와 새 캐릭터 추가

### 4-1. 기존 캐릭터 이미지 교체

1. 이미지 파일을 `public/units/`에 넣습니다. 예: `lumen-rifle.png`.
2. 해당 캐릭터의 `image`를 다음처럼 바꿉니다.

```ts
image: "/units/lumen-rifle.png",
```

3. 새 연습 경기를 열어 전장·상점·대기석·상세 정보에서 확인합니다.

투명 배경 PNG 또는 현재처럼 SVG를 사용할 수 있습니다. 파일명은 영문·숫자·하이픈으로 통일하면 경로 오류를 줄이기 쉽습니다. 대소문자를 정확히 맞추세요.

**새 유닛 이미지는 투명 배경 PNG, 500×500px 정사각형으로 제작하세요.** 몸 중심과 발 높이, 머리·총구 주변 여백을 캐릭터마다 비슷하게 맞춥니다. 이미지 안에는 이름·체력바·속성 표시를 넣지 않습니다. 작은 화면에서도 구분되는 실루엣을 우선합니다.

전장 전체와 각 칸은 정사각형이며 **8열×8행, 각 진영 4행**입니다. 화면은 반응형으로 줄어들며 이미지 원본을 화면에 500px로 크게 표시하는 것은 아닙니다. 논리 전장은 800×800, 칸 크기는 90이며 유닛의 기본 표시 영역은 81×81입니다.

[client/unit-appearance.ts](../client/unit-appearance.ts)의 `UNIT_IMAGE_BOX = CELL * 0.9`와 `unitImageSize()`가 표시 크기를 계산합니다. 500×500 이미지는 정사각형으로 맞추고, 기존 100×120 SVG 같은 세로형 이미지는 원본 비율을 유지해 영역 안에 넣습니다. 잘라내거나 가로·세로를 강제로 늘리지 않습니다. 호흡·반동의 일시적인 모션 배율은 별도로 적용됩니다. 좌우 방향은 그림 전체를 반전하며 처리합니다.

상점도 모든 캐릭터에서 `catalog.ts`에 등록된 이미지를 사용합니다. 실바·노바에 적용하던 별도 참고 이미지와 숨김 CSS는 0.20.18에서 제거했습니다.

총구 효과는 현재 이미지 속 실제 총구를 추적하지 않고 시전자 중심에서 대상 방향으로 오프셋을 주어 그립니다. 총 길이가 캐릭터마다 달라 정확한 총구 위치가 필요하면 6장의 무기별 위치 설정까지 연결해야 합니다.

### 4-2. 새로운 종류 추가 예시

예시 ID는 `commando`, 표시 이름은 `리온`입니다.

**① [shared/model.ts](../shared/model.ts)의 `Kind`에 새 ID를 추가합니다.**

```ts
export type Kind =
  | "knight" | "ranger" | "mage"
  | "warden" | "skirmisher" | "oracle"
  | "commando";
```

**② [shared/catalog.ts](../shared/catalog.ts)의 `UNITS` 객체 안에 새 항목을 추가합니다.** 기존 항목 사이의 쉼표와 객체 마지막의 `};`를 유지하세요.

```ts
commando: {
  name: "리온",
  attackAttribute: "yellow",
  defenseAttribute: "blue",
  rarity: 2,
  trait: "scout",
  role: "돌격 사수",
  image: "/units/commando.png",
  skills: ["piercingArrow", "quickstep"],
  stats: { ...BASE_COMBAT_STATS, hp: 190, attack: 23, defense: 10, interval: 800, range: 3, moveMs: 450 },
},
```

**③ 실제 이미지 `public/units/commando.png`를 추가합니다.** 위 경로는 예시이므로 파일을 직접 넣어야 합니다.

**④ 타입 검사 후 새 경기를 열고 상점에서 확인합니다.** `UNIT_KINDS`가 `UNITS`의 키에서 자동 생성되므로 상점 추첨과 이미지 사전 로딩에 연결됩니다. 현재 상점은 종류 목록에서 무작위로 선택하므로 새 캐릭터가 첫 상점에 반드시 나오지는 않습니다. 추가하면 전체 종류 수가 바뀌어 기존 캐릭터의 등장 확률도 달라집니다.

**⑤ 개발 프리셋·고정 테스트를 확인합니다.** `server/debug.ts`에는 특정 종류나 처음 몇 종류를 사용하는 구성이 있습니다. 새 종류를 등록했다고 모든 프리셋에 자동 배치되지는 않습니다. 새 캐릭터를 바로 시험하려면 연습용 프리셋 구성도 조정할 수 있습니다. 테스트의 고정 기대값은 변경한 규칙에 맞게 검토하세요.

기존 `trait` 중 하나를 배정하면 그 계열 계산에 포함됩니다. 새 계열까지 만들려면 `shared/model.ts`의 `Trait`과 [shared/synergy.ts](../shared/synergy.ts)의 `TRAITS`, 관련 UI도 수정합니다.

## 5. 스킬 설정과 공통 모션·효과 조절

### 5-1. 기존 스킬 배정

캐릭터 항목의 `skills`를 수정합니다.

```ts
skills: ["piercingArrow", "quickstep"],
```

이 예시는 기존의 관통 사격과 재빠른 발걸음을 조합합니다. 다른 캐릭터에 같은 스킬을 배정하면 같은 정의를 공유합니다. **스킬 정의 하나를 바꾸면 그 스킬을 사용하는 모든 캐릭터에 적용**됩니다. 캐릭터 전용 변형이 필요하면 새 스킬 ID로 복사해서 배정하세요.

### 5-2. 스킬 수치와 발동 조건

[shared/skill-catalog.ts](../shared/skill-catalog.ts)의 `SKILLS`에서 해당 ID를 찾습니다. 예를 들어 `piercingArrow`의 `attackScale`은 공격력 계수이고 `resource.max`는 최대 코스트입니다.

| 설정 | 의미 |
| --- | --- |
| `image` | 스킬 칸/툴팁의 정사각형 이미지 경로. 예: `/skills/guardian.svg`. 실제 파일은 `public/skills/`에 넣으며 생략 시 공용 그림 사용 |
| `description` | 사용자에게 보여주는 설명. 수치를 바꾸면 설명도 수정 |
| `triggers` | `costFull`, `battleStart`, `afterBasicAttack`, `onDamaged` 등의 발동 계기 |
| `resource` | 최대 코스트, 초당/처치 시 회복량. 공격/피격 회복값은 공통 5/3에 더하는 추가량 |
| `cooldownMs` | 재사용 대기시간, 밀리초 |
| `target` | 자신, 가까운 적, 낮은 체력 아군 등 대상 규칙과 사거리·반경 |
| `effects` | 피해·회복·배리어·버프 |
| `activation` | 즉시 발동 또는 코스트를 소모하며 유지 |

지원되는 타입은 [shared/skill-types.ts](../shared/skill-types.ts), 실제 판정은 [shared/skills.ts](../shared/skills.ts)에 있습니다. 기존 타입 안에서 수치·대상을 바꾸는 일과 새로운 효과 종류를 만드는 일은 작업 범위가 다릅니다. 예를 들어 아직 없는 탄약·재장전 규칙은 스킬 이름 변경만으로 구현되지 않습니다. 자세한 규칙은 [스킬 안내](SKILLS.md)를 참고하세요.

v0.20.46부터 설명에 `공격 주기 −150ms`, `이동 주기 −100ms` 형식으로 쓴 보정은 [shared/skill-description.ts](../shared/skill-description.ts)의 `skillDescriptionFor()`가 화면에서 백분율로 바꿉니다. 해당 유닛의 장비 등을 반영한 표시 능력치와 실제 100ms 진행 간격을 기준으로 환산합니다. 카이는 공격 900→700ms이므로 22.2% 감소, 이동 400→300ms이므로 25% 감소로 보입니다. 다른 유닛에게 배정하면 그 유닛의 주기를 기준으로 다시 계산합니다. 이는 설명의 환산이며 실제 `effects[].modifiers.stats.interval/moveMs`의 고정 보정은 그대로입니다. 스킬 수치를 수정하면 설명의 보정량도 함께 수정하세요.

스킬 카드의 발동 빛은 [client/skill-presentation.ts](../client/skill-presentation.ts)의 `SKILL_FLASH_MS`(현재 500ms)와 `SkillCastFeedback`에서 관리합니다. `activations` 증가를 감지하며 패킷 반복·재접속에 과거 효과를 재생하지 않습니다. 지속 상태는 실제 `active` 값, 사용 완료는 `maxActivationsPerBattle`과 `activations`를 비교합니다. 카드의 노랑/초록/회색은 UI 상태색이며 전장의 공격·방어 속성색과 별도로 관리합니다. v0.20.61부터 칸에는 이미지·이름·종류·필요 코스트만 남겼으며, v0.20.62부터 긴 설명과 현재 상태는 PC 호버·모바일 터치 툴팁으로 확인합니다. 유닛 이름과 전투 불능 문구는 생략합니다. 칸/툴팁 생성은 [client/skill-ui.ts](../client/skill-ui.ts), 유닛 데이터 연결은 `main.ts`의 `renderSkills()`·`createSkillDetailsUI()` 호출부, 모양은 `style.css`의 0.20.61~62 부분을 수정하세요.

### 5-3. 공통 모션 수치

[client/unit-motion.ts](../client/unit-motion.ts)에서 다음 식 또는 이름을 검색합니다. **현재 이 파일의 공통 수치를 바꾸면 모든 캐릭터에 적용됩니다.**

| 바꾸려는 느낌 | 찾을 부분 | 현재 기준 |
| --- | --- | --- |
| 발사 반동의 지속·정점 시간 | `pulse(now, state.recoil, 180, 28)` | 총 180ms, 28ms에 최대 |
| 발사 시 밀리는 거리 | `state.recoil`을 사용하는 x/y 식의 `* 5` | 방향을 따라 최대 약 5 논리 픽셀 |
| 피격 반동의 지속·정점 시간 | `pulse(now, state.hit, 220, 24)` | 총 220ms, 24ms에 최대 |
| 피격 시 밀리는 거리 | `state.hit`을 사용하는 x/y 식의 `* 7` | 방향을 따라 최대 약 7 논리 픽셀 |
| 이동 기울기 | `const tilt`의 `* 6` | 약 6도 |
| 호흡 속도 | `Math.sin(now / 620 + phase)` | 분모가 클수록 느린 변화 |
| 호흡의 크기 | `breath`가 들어가는 `scaleX`, `scaleY`, y 식 | 가로 0.004, 세로 0.008, 위치는 실제 표시 높이에 맞춰 보정 |
| 스킬 발동 자세 | `state.castAt`와 `340, 65` | 총 340ms, 65ms에 최대 |
| 사망 동작 시간 | `DEATH_DURATION` | 420ms |

반동 거리를 바꿀 때는 x/y에 쓰인 값을 함께 확인하세요. 최대 변위는 별도의 `clamp(..., -10, 10)`으로도 제한합니다. 호흡의 세로 배율과 위치 보정은 발이 떠 보이지 않도록 함께 조절합니다.

그림의 결과 위치는 [client/board.ts](../client/board.ts)가 적용합니다. `this.motion.update`, `this.motion.pose`, `sprite.setPosition`을 검색하면 연결 지점을 찾을 수 있습니다. 전장 칸·체력바·이름 위치 대신 **그림에만 모션 오프셋을 적용하는 구조**를 유지하세요.

### 5-4. 총격·배리어·스킬 효과

[client/combat-effects.ts](../client/combat-effects.ts)에서 아래 함수 이름을 검색합니다.

| 함수/설정 | 담당 |
| --- | --- |
| `muzzleAndTracer` | 총구 섬광, 탄도 모양·길이·수명 |
| `impact` | 몸체 피격 충격파·스파크·색조 |
| `barrierHit` | 배리어 피격 방향 파문, 파괴 윤곽·파편 |
| `damageNumber` | 피해 숫자의 글꼴·크기·상승·수명 |
| `skillCast` | 스킬 발동 링·응축 표시·이름 |
| `skillEnd` | 유지 스킬 종료 표시 |
| `heal` | 대상의 회복 효과 |
| `play`의 `shield` 분기 | 배리어 생성 효과 |
| `keep` | 일시 효과의 페이드·이동·수명 종료 정리 |

색상을 고정 숫자로 덮어쓰기보다 기존 공격/방어 속성색을 전달해 사용하는 방식을 유지하세요. 많은 효과가 겹칠 때는 부가 파편을 제한하며, 피해 숫자는 남기도록 구성되어 있습니다. 새 효과도 `keep()`으로 수명과 제거를 관리하면 장면 초기화 때 함께 정리됩니다.

추가로 [client/skill-indicator.ts](../client/skill-indicator.ts)의 `charge >= 0.65`는 코스트 링이 보이기 시작하는 기준입니다. 링의 실제 모양은 `board.ts`의 `indicator.visible` 분기에서 그립니다. 체력바 잔상은 [client/health-trail.ts](../client/health-trail.ts)의 `HEALTH_TRAIL_HOLD`와 감소 식에서 조절합니다.

## 6. 캐릭터별 무기·모션 설정으로 확장하기 — 아직 미구현

이 장은 앞으로 개발할 때의 설계 안내입니다. 다음 설정은 **현재 붙여 넣어 사용할 수 있는 기능이 아닙니다.**

```ts
// 향후 캐릭터 설정에 추가할 항목의 예시
weaponType: "rifle",
motionProfile: "heavy",
```

### 6-1. 권장 연결 순서

1. **무기 설정 파일을 만듭니다.** 예: `shared/weapon-catalog.ts`. 권총·소총·기관단총·산탄총·저격총 등의 ID와 총구 섬광 크기, 탄도 폭/수명, 시각적 산탄 수, 총구 위치 오프셋을 정의합니다.
2. **모션 설정 파일을 만듭니다.** 예: `shared/motion-catalog.ts`. 기본형·민첩형·중장형 등의 ID와 반동 거리/시간, 호흡 크기, 이동 기울기, 발동 자세 수치를 정의합니다. 이 두 파일은 새로 만들 파일입니다.
3. **캐릭터 정의의 타입을 확장합니다.** `catalog.ts`의 `UNITS` 값 타입에 `weaponType`, `motionProfile`을 추가하고 유효한 ID 타입에 연결합니다. 기존 여섯 캐릭터에도 기본값을 지정합니다.
4. **무기 설정을 효과에 연결합니다.** `combat-effects.ts`에서 `source.kind` → `UNITS[source.kind].weaponType` → 무기 설정 순서로 읽고, `muzzleAndTracer` 등의 공통 숫자를 해당 설정으로 바꿉니다.
5. **모션 설정을 움직임에 연결합니다.** `board.ts`에서 캐릭터의 모션 프로필을 찾아 `UnitMotion.update()` 등에 전달하고, `unit-motion.ts`가 프로필별 수치를 저장·사용하도록 타입과 계산식을 확장합니다. 현재 `UnitMotion`은 캐릭터 종류나 프로필을 직접 받지 않습니다.
6. **같은 무기/프로필을 공유하는 다른 캐릭터도 함께 확인합니다.** 특정 캐릭터만 다르게 만들려면 별도의 프로필 ID를 만들어 배정합니다.

공격 속성은 색상, 무기는 발사 형태, 모션 프로필은 몸의 움직임으로 역할을 나누면 조합하기 쉽습니다. 예를 들어 같은 소총을 빨강 속성과 파랑 속성 캐릭터가 각각 다른 모션으로 사용할 수 있습니다.

### 6-2. 연출과 실제 공격 규칙의 차이

| 원하는 변화 | 필요한 수정 |
| --- | --- |
| 소총 탄도를 더 길고 가늘게 표현 | 클라이언트 무기 효과 |
| 산탄이 여러 갈래로 보이게 표현 | 클라이언트 무기 효과. 실제 피해 횟수는 그대로 |
| 기본 공격을 더 자주 하게 변경 | 캐릭터의 `stats.interval` 또는 서버 버프 규칙 |
| 실제로 여러 적에게 피해를 주는 산탄 공격 | 서버 대상 선정·피해 처리 또는 스킬 규칙 |
| 실제 탄약·재장전 도입 | 서버 상태와 공격 규칙, 상태 전송, UI/모션 |
| 전투 중 무기 교체 | 개별 Unit/Fighter 상태, 서버 검증, `snapshot.ts` 전달, 표시 연결 |

캐릭터 종류별로 고정된 시각 설정은 `kind`로 카탈로그를 조회할 수 있습니다. 개별 유닛이 경기 중 바꾸는 무기·속성이라면 종류의 기본값만으로 표현할 수 없으므로 별도 상태가 필요합니다.

## 7. 실제 프레임 애니메이션 추가하기 — 아직 미구현

현재 전장 캐릭터는 `Phaser.GameObjects.Image`입니다. 호흡·반동·사망 동작은 한 장의 그림의 위치·회전·배율·투명도를 바꾸어 표현합니다.

팔을 움직이는 사격, 다리를 움직이는 걷기, 탄창을 교체하는 재장전에는 동작별 그림이 필요합니다. 다음 순서로 확장합니다.

1. 대기·이동·사격·피격·사망·스킬 등의 프레임을 같은 캔버스 크기와 발 기준점으로 제작합니다. 스프라이트 시트라면 프레임 가로/세로 크기와 각 동작의 시작·끝 번호를 기록합니다.
2. `board.ts`의 `preload()`를 스프라이트 시트 또는 아틀라스 로딩에 맞게 확장합니다.
3. `board.ts`의 `.image(...)` 생성과 이미지 타입을 `Sprite`에 맞게 변경하고 동작별 애니메이션을 등록합니다. `combat-effects.ts`의 `EffectUnit.sprite` 등 연결 타입도 함께 확인합니다.
4. 이동/사망 상태와 `attack`, `skillStart`, 피격 이벤트에 맞춰 동작을 전환합니다. 같은 snapshot이 반복될 때마다 사격·사망 프레임을 처음부터 다시 시작하지 않도록 기존 이벤트 ID 중복 방지를 유지합니다.
5. 사망·피격·사격·이동·대기 동작의 우선순위를 정하고, 끝나는 동작은 현재 상태에 맞는 기본 동작으로 복귀시킵니다.
6. 상점·대기석·상세 정보는 HTML `<img>`도 사용하므로 **대표 정지 이미지를 따로 유지**합니다. 스프라이트 시트 전체를 기존 `image`에 넣으면 UI에 시트 전체가 보일 수 있습니다.

프레임 동작과 현재 위치·배율 모션을 동시에 크게 적용하면 반동이 과해질 수 있으므로 모션 프로필과 함께 조절합니다. 효과 줄이기 모드에서도 캐릭터와 필수 상태를 알아볼 수 있게 확인하세요.

## 8. 속성 상성·서버 상태를 추가할 때

현재 네 가지 공격/방어 속성은 **색상 분류**이며 속성별 피해 배율은 없습니다.

속성 상성을 만들려면 [shared/skills.ts](../shared/skills.ts)의 공통 `damage()` 경로에 공격 속성·방어 속성에 따른 규칙을 연결합니다. 피해 감소·배리어 흡수·실제 체력 감소·기여도 집계와 적용 순서도 정해야 합니다. 기본 공격과 스킬이 같은 규칙을 사용하는지 검사하세요.

브라우저 효과에서 체력을 직접 줄이거나 피해 이벤트를 추가해 판정을 흉내 내지 않습니다. 서버가 판정하고 클라이언트는 그 결과를 표시하는 구조입니다.

현재 피해 이벤트의 의미는 다음과 같습니다.

| 필드 | 의미 |
| --- | --- |
| `amount` | 실제로 감소한 체력. 남은 체력으로 제한됨 |
| `shieldDamage` | 해당 타격에서 배리어가 흡수한 양 |
| `healthDamage` | 배리어를 넘어간 표시용 피해. 남은 체력보다 큰 초과 피해도 포함 |
| `shieldBroken` | 해당 타격에서 배리어가 소진되었는지 |
| `critical` | 해당 타격이 치명타인지. 기본 공격·공격 스킬 이벤트에만 포함 |

배리어 피해는 공격 이벤트에 기록된 값을 사용합니다. 표시 시점의 남은 배리어로 다시 추정하면 연속 공격이나 같은 전송 안의 재생성 상황에서 잘못 표시될 수 있습니다.

새 상태를 브라우저에 보내야 한다면 `shared/model.ts`뿐 아니라 [shared/snapshot.ts](../shared/snapshot.ts)의 명시적 필드 복사도 수정합니다. 상대 상점·경제·보관 장비와 내부 난수 상태 등 비공개 정보가공개되지 않도록 기존 전송 범위를 유지합니다. 상대 전장과 대기석의 유닛·착용 장비는 현재 관전용 공개 정보입니다.

## 9. 수정 후 확인 절차

### 9-1. 기본 검사

PowerShell에서 아래 명령을 하나씩 실행합니다. 오류가 생기면 첫 오류부터 수정합니다.

```powershell
npm.cmd run check
npm.cmd test
npm.cmd run build
```

피해·스킬 판정이나 전송 상태를 변경했다면 실제 서버 통신 검사도 실행합니다.

```powershell
npm.cmd run test:network
```

### 9-2. 관련 브라우저 검사

브라우저 검사 도구는 처음에 설치합니다. 게임 실행용 의존성과는 별도로 설치되며 다운로드가 필요합니다.

```powershell
npm.cmd run setup:browser
```

자동 설치 대신 설치된 Chrome을 사용할 때는 실제 실행 파일 경로를 확인하여 지정할 수 있습니다. `CHROME_PATH`만 지정해도 Playwright 검사 도구 설치는 필요합니다.

```powershell
$env:CHROME_PATH = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
```

모든 검사를 매번 돌리기보다 수정한 부분에 맞춰 실행합니다. 같은 검사나 포트가 겹치는 검사를 동시에 실행하지 마세요.

| 변경 내용 | 검사 명령 |
| --- | --- |
| 속성색·피해 숫자·배리어 관통 표시 | `npm.cmd run test:combat-attributes:browser` |
| 방향·반동·이동·사망 | `npm.cmd run test:unit-motion:browser` |
| 총구 섬광·탄도·명중 스파크 | `npm.cmd run test:gun-effects:browser` |
| 배리어 피격/파괴·체력바 잔상 | `npm.cmd run test:barrier:browser` |
| 호흡·스킬 충전/발동/유지/종료·회복 | `npm.cmd run test:idle-skills:browser` |
| 500×500·기존 세로형 이미지 비율, 정사각형 캔버스 | `npm.cmd run test:square-units:browser` |
| 8×8 전장 배치·선택·드래그 | `npm.cmd run test:board:browser` |

기존 검사는 기존 색상·수치·캐릭터 구성을 기대할 수 있습니다. 의도적으로 규칙을 바꿨다면 실패 내용을 읽고 관련 기대값과 실제 동작을 함께 검토합니다. 새 무기·캐릭터의 고유 동작은 별도 검증 항목도 추가해야 합니다.

### 9-3. 화면에서 직접 확인

- PC와 좁은 모바일 폭, 양쪽 플레이어 시점에서 방향·크기·이름·체력바를 봅니다.
- 대기 → 이동 → 공격 → 피격 → 사망, 스킬 충전 → 발동 → 유지 → 종료를 확인합니다.
- 배리어 없음, 전부 흡수, 정확히 소진, 배리어 초과 피해를 각각 확인합니다.
- 효과 줄이기를 켜고 껐을 때 남은 파편·회전·색조가 정리되는지 확인합니다.
- 새 연습 경기와 라운드 변경 후 이전 모션·피해 숫자가 남지 않는지 봅니다.

반복 전투에는 `npm.cmd run dev:debug`를 사용할 수 있습니다. 일반 개발 서버를 종료한 뒤 실행하고, 연습 경기의 개발 패널에서 시작 상태·저장·복원을 사용합니다. 서버 전투를 일시정지해도 클라이언트의 짧은 시각 효과가 영상 프레임처럼 정지·복원되는 기능은 아닙니다. 안내는 [개발 디버깅](DEBUGGING.md)을 참고하세요.

## 10. 자주 생기는 문제

| 증상 | 먼저 확인할 곳 |
| --- | --- |
| `weaponType` / `motionProfile`을 넣자 타입 오류 | 현재 미구현 항목. 6장의 타입·데이터·클라이언트 연결 개발이 먼저 필요 |
| 새 캐릭터 ID를 추가하자 타입 오류 | `Kind`와 `UNITS` 양쪽 등록, 필수 필드 누락·철자·쉼표 |
| 이미지가 안 보임 | 실제 파일 존재, 파일명 대소문자, `/units/...` 경로, 브라우저 새로고침 |
| 이미지가 너무 작거나 늘어남 | 그림의 투명 여백·캔버스 비율, `board.ts`의 표시 크기 |
| 그림만 바꿨는데 총구 위치가 어긋남 | 현재 공통 중심 오프셋 사용. 무기별 위치 연결 필요 |
| 공격 속성을 바꿨는데 피격 파편은 다른 색 | 정상 규칙일 수 있음. 파편은 대상 방어색, 체력 피해 숫자는 공격색 |
| 배리어 피해 숫자가 계속 연한 파랑 | 고정색 규칙. `BARRIER_DAMAGE_COLOR`를 별도로 관리 |
| 모션을 바꿨더니 모든 캐릭터가 같이 바뀜 | 현재 공통 수치 사용. 개별 차이는 모션 프로필 구조 필요 |
| 스킬 설명만 바뀌고 성능은 같음 | `description`과 실제 `effects`/`resource` 등의 수치는 별도 |
| 새 스킬이 발동하지 않음 | ID 일치, 트리거·코스트·쿨다운·대상 사거리·대상 존재 여부 |
| 능력치 변경이 진행 중 전투에 안 보임 | 서버 재시작 여부와 새 경기/전투의 Fighter 생성 시점 확인 |
| 수정했는데 빌드 화면에는 예전 모습 | 개발 화면 5173과 빌드 화면 2567 구분, 재빌드 또는 `npm start` 재실행 |
| 서버 시작 시 주소/포트 사용 중 오류 | 이전 개발/게임 서버를 Ctrl+C로 종료한 후 하나만 실행 |
| 터미널에서 `npm.ps1` 실행 정책 오류 | 이 문서처럼 `npm.cmd`로 실행 |

## 11. 다음 캐릭터를 준비할 때 적어둘 양식

아래 표를 캐릭터마다 작성하면 실제 설정 작업을 진행하기 쉽습니다. 무기 종류·모션 프로필·프레임 동작은 구현 상태를 함께 기록하세요.

| 항목 | 작성 내용 |
| --- | --- |
| 표시 이름 / 내부 ID | 예: 리온 / commando |
| 대표 이미지 | 파일명과 실제 저장 위치 |
| 공격 / 방어 속성 | 예: 노랑 / 파랑 |
| 희귀도 / 계열 | 예: 2 / 정찰(`scout`) |
| 체력 / 공격력 | 기본값 |
| 공격 주기 / 사거리 / 이동 주기 | ms / 칸 / ms |
| 액티브 / 패시브 스킬 | 기존 ID 또는 신규 스킬의 조건·효과 |
| 무기 종류 | 원하는 종류, 공통 연출 사용 또는 개별 구현 필요 여부 |
| 모션 특징 | 반동 강도, 호흡, 이동 자세, 발동 자세 |
| 실제 프레임 동작 | 필요한 동작과 프레임 준비 여부 |
| 확인할 상황 | 배리어 관통, 연속 공격, 사망 등 |

작은 수정은 **설정 하나 변경 → 타입 검사 → 새 연습 경기 확인** 순서로 진행하면 원인을 찾기 쉽습니다. 변경을 마친 뒤에는 수정 파일과 결과를 간단히 기록해 두세요.
