# 스킬 시스템 사용 안내 — v0.20.62

## 선택 유닛의 스킬 표시

스킬 칸은 이미지·이름·액티브/패시브·필요 코스트만 표시합니다. 필요 코스트는 `resource.max`, 코스트가 없으면 0입니다. PC는 마우스를 올리거나 키보드로 포커스하고, 모바일은 터치하면 **칸 옆 툴팁**에서 상세 설명과 실시간 코스트·재사용/지속/사용 완료 상태를 확인합니다. 캐릭터 이름과 `전투 불능` 문구는 표시하지 않습니다. PC는 마우스를 떼면, 모바일은 같은 칸을 다시 터치하면 닫습니다. 바깥 터치·Esc로도 닫으며 아래 유닛 상세와 게임 조작을 추가로 잠그지 않습니다. 노란 발동 빛과 초록 지속 효과는 스킬 칸에 유지합니다.

`shared/skill-catalog.ts`에서 `image: "/skills/guardian.svg"`처럼 그림을 설정합니다. 실제 파일은 `public/skills/`에 넣고 경로에 `public`을 쓰지 않습니다. 현재 12종은 64×64 SVG이며 정사각형 PNG도 사용할 수 있습니다. `image`를 생략하면 `/skills/default.svg`를 표시합니다. 스킬마다 이미지와 이름이 함께 보여 색상만으로 구분하지 않습니다.

스킬 버튼과 툴팁: `client/skill-ui.ts`. 선택 유닛/관전 데이터 연결: `client/main.ts`의 `renderSkills()`·`createSkillDetailsUI()` 호출부. 발동 감지: `client/skill-presentation.ts`. 모양: `client/style.css`의 0.20.61~62 부분. 설명의 주기 % 환산: `shared/skill-description.ts`. 칸을 눌러도 직접 스킬을 시전하지 않습니다.

액티브와 패시브는 모두 서버에서 자동 발동합니다. **액티브 = 수동 버튼**이 아닙니다. 오토체스이므로 조건을 만족하면 액티브도 자동 시전합니다. `kind`는 스킬 분류이고, 실제 발동·코스트·지속 방식은 별도 설정으로 정합니다.

코스트가 있는 모든 스킬은 기본 공격 시 **5**, 살아 있는 상태에서 실제 피해를 받으면 **3**을 회복합니다. 배리어로 흡수한 타격도 피격에 포함하며 피해가 0이거나 사망한 경우 피격 코스트를 지급하지 않습니다. 스킬별 `perBasicAttack`·`perDamaged`는 이 기본값에 추가됩니다. 지속형은 기존 규칙대로 `recoverWhileActive`를 별도로 켜지 않으면 유지 중 회복하지 않습니다. 공통 수치는 `shared/skills.ts`의 `BASIC_ATTACK_COST`·`DAMAGED_COST`에서 수정합니다. 예를 들어 관통 사격은 기본 공격당 5+20=25, 철벽 방패는 피격당 3+10=13입니다.

치유는 사망 유닛을 제외하고 최대 체력을 넘지 않습니다. 범위 내 모두 건강해도 충전이 완료되면 치유사가 시전하고 코스트를 소비합니다. 피해는 기존 서버 경로에서 정수 반올림하며, 비율 회복은 기존 방식대로 소수 체력을 허용합니다. 시너지로 늘어난 최대 체력은 비율 회복에도 반영됩니다.

수치는 기능 확인용입니다. 전투 밸런스는 별도로 조정해야 합니다.

## 코스트 구조

현재는 **스킬별 독립 코스트**입니다. 캐릭터 하나의 코스트를 여러 스킬이 공유하지 않으므로 스킬 추가 시 자원 경쟁으로 발동 순서가 바뀌지 않습니다.

```ts
resource: {
  max: 100,
  initial: 0,
  regenPerSecond: 10, // 시간이 지날 때 초당 회복
  perBasicAttack: 15, // 자신의 기본 공격마다 회복
  perDamaged: 5,     // 피해 판정을 받을 때 회복 (보호막으로 막은 유효 피격도 포함)
  perKill: 20,       // 기본 공격 또는 스킬로 적을 처치했을 때 회복
  recoverWhileActive: false,
}
```

시간 회복과 공격 회복 등을 동시에 넣을 수 있습니다. 코스트는 0~max로 제한되며 초과 충전분은 버립니다. 스킬 피해는 기본 공격 횟수와 `perBasicAttack`을 늘리지 않습니다.

`recoverWhileActive`는 지속형 효과 도중 회복 허용 여부입니다. 기본은 false입니다. true에서 초당 회복이 초당 소모 이상이면 코스트가 고갈되지 않을 수 있습니다. 이것이 의도한 동작인지 확인하세요.

## 트리거와 조건

`triggers` 배열은 OR입니다. 한 항목이라도 만족하면 시전을 시도합니다.

| on | 평가 시점 |
| --- | --- |
| `battleStart` | 전투 시작, 장비 시작 효과 적용 후 |
| `tick` | 서버 전투의 매 100ms 단계 |
| `afterBasicAttack` | 자신의 기본 공격 처리 후 |
| `onDamaged` | 피격 처리 후 아직 살아 있을 때 |
| `onKill` | 자신이 적을 처치했을 때 |
| `costFull` | 시간·공격·피격·처치로 코스트가 차거나, 최대 코스트를 유지 중일 때 |

`costFull`은 단 한 번의 경계 통과 이벤트가 아닙니다. 대상이 없거나 쿨다운 중이면 **최대 코스트를 유지하며 나중에 다시 평가**합니다.

`when`에는 아래 조건을 조합합니다.

```ts
triggers: [{
  on: 'costFull',
  when: {
    all: [
      { type: 'hpBelow', ratio: 0.5 },
      { type: 'elapsedAtLeast', ms: 5000 },
      { any: [
        { type: 'enemyInRange', range: 2 },
        { not: { type: 'hpBelow', ratio: 0.2 } },
      ] },
    ],
  },
}],
```

이 예시는 최대 코스트 + 체력 50% 이하 + 전투 5초 경과를 모두 요구하고, 마지막 묶음 안에서는 두 조건 중 하나를 만족하면 됩니다.

추가 조건:

- `{ type: 'costAtLeast', amount: 50 }`: 특정 코스트 이상
- `{ type: 'attacksEvery', count: 3 }`: 기본 공격 횟수가 3의 배수 (0회 제외). 보통 `afterBasicAttack`과 함께 사용
- `{ type: 'damageSource', source: 'basic' }`: 기본 공격에 의한 피격·처치만. `skill`도 지원

## 즉시 발동 예제

`SKILLS`에 아래 정의를 넣고 캐릭터의 `skills` 배열에 `mixedStrike`를 추가하면 됩니다.

```ts
mixedStrike: {
  id: 'mixedStrike',
  name: '혼합 충전 강타',
  description: '초당 8, 공격마다 12 충전. 최대 충전 시 강타.',
  kind: 'active',
  triggers: [{ on: 'costFull' }],
  resource: { max: 100, regenPerSecond: 8, perBasicAttack: 12 },
  cooldownMs: 1000,
  target: { kind: 'nearestEnemy', range: 3 },
  effects: [{ type: 'damage', amount: 20, attackScale: 1.5 }],
  activation: { mode: 'instant', spend: 'all' },
},
```

`spend: 50`처럼 고정 수량을 소비할 수도 있습니다. 코스트가 부족하면 시전하지 않습니다. `spend` 생략은 0 소비입니다. 자원이 없는 패시브에 적합합니다. 0 소비 스킬은 별도의 쿨다운이나 횟수 제한을 의도대로 지정하세요.

## 최대 코스트 → 점진 소모형 예제

```ts
burningAura: {
  id: 'burningAura',
  name: '연소 오라',
  description: '최대 충전 후 5초 동안 공격력 상승과 주기 피해.',
  kind: 'active',
  triggers: [{ on: 'costFull' }],
  resource: { max: 100, regenPerSecond: 15 },
  cooldownMs: 2000,
  target: { kind: 'allEnemies', range: 2 },
  effects: [], // 켜질 때 한 번 적용할 효과. 여기서는 없음
  activation: {
    mode: 'sustain',
    drainPerSecond: 20, // 100 / 20 = 5초, 유지 중 회복은 기본 차단
    modifiers: { stats: { attack: 10 }, damageTakenMultiplier: 0.8 },
    pulse: { everyMs: 1000, effects: [{ type: 'damage', amount: 12 }] },
  },
},
```

- 최대 코스트를 한 번에 지우지 않고 유지 중 서서히 소모합니다.
- `modifiers`는 시전자에게만 적용되며, 종료 즉시 사라집니다.
- `effects`는 발동 순간 대상에게 한 번 적용합니다.
- `pulse.effects`는 지정 주기마다 **현재 범위의 살아 있는 대상**을 다시 선택하여 적용합니다.
- 정확히 코스트가 0이 되는 시각에는 추가 펄스를 주지 않습니다.
- 지속형 쿨다운은 **효과 종료 시각부터**, 즉시형 쿨다운은 **발동 시각부터** 계산합니다.
- 사망·전투 종료·진행 중 경기 이탈로 종료되면 유지 효과도 해제합니다.
- 공격 속도 변경은 다음 공격 주기를 예약할 때 적용합니다. 이미 예약한 공격 시각을 소급 변경하지 않습니다.
- `target`이 적이면 발동 순간 범위에 적이 있어야 합니다. 적과 무관한 자기 강화는 `target: {kind:'self'}`로 지정하세요.

## 대상과 효과

대상: `self`, `nearestEnemy`, `allEnemies`, `lowestHealthAlly`. range는 맨해튼 거리입니다. `radius`는 선택한 첫 대상 주변의 같은 진영 대상까지 효과를 확장합니다. 반경 확장의 기준은 최초 대상이며, 주변 대상은 시전자의 range 밖이어도 포함될 수 있습니다.

효과:

```ts
{ type: 'damage', amount: 30, attackScale: 0.5 }
{ type: 'heal', amount: 10, maxHpRatio: 0.05 }
{ type: 'shield', amount: 40 }
{ type: 'buff', durationMs: 3000,
  modifiers: { stats: { attack: 10, interval: -100 }, damageTakenMultiplier: 0.9 } }
```

기본·장비 능력치에 일시 보정을 별도로 합산하므로 효과가 끝나도 원본 능력치가 손상되지 않습니다. 변경 가능한 전투 능력치는 attack, interval, range, moveMs입니다. interval/moveMs는 최소 100ms, range는 최소 1입니다. 현재 최대 체력 자체를 바꾸는 버프는 제공하지 않습니다.

같은 시전자·같은 스킬의 buff는 중첩하지 않고 갱신합니다. 한 스킬 안의 buff 보정은 한 효과에 합쳐 작성하세요. 피해 감소 배수는 여러 효과 사이에 곱셈으로 합성합니다.

보호막과 회복은 이미 지급한 값이므로 지속형 종료 시 회수하지 않습니다. 유지 중에만 필요한 능력치 효과는 `activation.modifiers`를 사용하세요. `effects`로 지급한 유한 시간 buff는 자기 expiresAt까지 유지됩니다. 전투 종료와 해당 유닛 사망 시 정리됩니다.

## 서버 판정과 안전한 실행

- 스킬 ID는 서버의 캐릭터 정의에서 정합니다. 브라우저가 임의의 스킬·코스트·피해량을 전송하여 바꿀 수 없습니다.
- 모든 스킬 상태는 기본 전투 상태와 함께 Colyseus 스냅샷으로 두 참가자에게 전달됩니다.
- 각 스킬은 동일한 시뮬레이션 시각에 한 번만 발동합니다. 스킬 피해는 기본 공격 회복을 재귀 호출하지 않습니다.
- 스킬 피해도 장비의 onHit, 보호막, 피해 감소, 사망·처치 처리 경로를 통과합니다.
- 장비 afterAttack의 damage에는 방어와 보호막을 통과해 실제로 줄어든 체력을 전달합니다.
- 라운드마다 SkillState, 코스트, 시전 횟수, 버프, 기본 공격 횟수를 새로 생성합니다.
- 100ms 고정 단계로 밀린 전투를 처리합니다. 같은 시간 경과라면 서버 콜백 간격이 불규칙해도 같은 결과를 냅니다. 실제 표현에는 네트워크 및 100ms 단계 지연이 있습니다.
- 스턴·침묵·캐스팅 선딜·공유 마나·장비로 스킬 교체·사용자 작성 스크립트 실행은 현재 범위에 포함되지 않습니다. 추가 시 이 자료구조와 서버 검증 경로를 확장하세요.
