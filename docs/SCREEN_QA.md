TypeScript/Vite 빌드와 기존 화면 모드 브라우저 검사를 통과했습니다. PC 1440×1000·1920×1080·1024×768, 모바일 390×844·320×740·844×390의 6가지 크기에서 footer의 버전 중앙 정렬, 오른쪽 화면 설정, 가로 넘침 없음, 스크롤 끝에서 고정 게임 버튼과 겹침 없음, 화면 선택 버튼 접근을 확인했습니다. UA 기본값·수동 변경·저장·새로고침·자동 복원·창 크기 변경·로비 비활성화가 정상입니다. 서버/shared 및 client/net.ts는 0.17.0과 동일합니다.

Linux headless Chromium 138.0.7204.0에서 검사했습니다. 실제 휴대폰/Safari/Firefox 검사는 포함하지 않습니다. [PC footer](screenshots/footer/pc-footer-0.17.1.png), [모바일 footer](screenshots/footer/mobile-footer-0.17.1.png), [정렬 측정 결과](screenshots/footer/metrics.json)를 참고하세요. 게임 실행은 `npm ci` → `npm start`, 화면 모드 검사는 `npm run setup:browser` → `npm run test:screen-mode:browser`입니다.

# 0.17.0 화면 검증

Linux headless Chromium 138.0.7204.0 / Playwright 1.62.1에서 실행했습니다. PC는 Windows UA와 마우스, 모바일은 Android UA와 실제 CDP 터치 이벤트를 사용했습니다. 실제 Windows/macOS/휴대폰/Safari/Firefox 직접 검사는 포함하지 않습니다.

- TypeScript/Vite 빌드 통과. 규칙·입력 테스트 **173개 통과, 실패 0개**.
- 하단 창: PC 6가지 크기(1440×1000, 1920×1080, 1366×768, 1024×768, 844×390, 390×844), 모바일 7가지 크기(390×844, 320×740, 360×640, 414×896, 768×1024, 844×390, 480×320). 상점/대기석 두 탭을 각각 측정하여 총 26개 결과를 기록했습니다.
- 같은 화면 크기에서 탭 높이 동일, 경험치 왼쪽/준비 오른쪽 분리, 48px 버튼과 최소 44px 주요 조작 영역, 버튼과 전장 겹침 방지, 가로 넘침 없음, 페이지 스크롤 후 고정 위치를 확인했습니다. 높이 640px 이상 검사 화면에서 전장 전체를 볼 수 있고, 넓은 PC 화면은 전장 560px를 유지합니다. 매우 낮은 가로 창은 내부 스크롤이나 접기가 필요합니다.
- 탭 키보드 전환, 접기 후 경험치/준비 버튼 유지, 대기석 12칸 접근, 탭 저장·새로고침·모드 변경, PC 마우스/모바일 터치 유닛 교환, 상세 정보와 기존 착용 장비 관리, 로비 비활성화를 확인했습니다.
- 장비를 전장 및 대기석 유닛에게 직접 드래그하여 장착하고 서버 상태와 배지를 확인했습니다. 드래그 중 대상 이름·성급·장착 가능 여부·유닛 강조 표시를 확인했습니다. 기존 선택 유닛과 드롭 대상이 달라도 드롭한 유닛에게 장착됩니다.
- 상대/빈 칸/장비 2개 보유 유닛/재료/전투 중 드롭을 거부합니다. Escape·터치 취소·크기 변경 후 취소, 드래그 중 전장과 하단 창 크기 유지, 드롭 후 잘못된 호환 클릭 방지를 확인했습니다. 준비/경험치 버튼 위에 장비를 놓아도 해당 버튼이 실행되지 않습니다.
- 장비 선택 후 클릭/키보드로 대상 지정, 장비 해제 후 보관함 복귀, 제작 관리 바로 열기와 재료 조합, 대기석에서 경험치 구매, 전투 중 상점 구매·리롤을 확인했습니다.
- 기존 보상 팝업/눈 버튼·제작, UA/수동 화면 모드, 모바일 유닛 교환, 기록/기여도, 최종 결과 브라우저 검사도 모두 통과했습니다. JavaScript 오류는 없었습니다.
- server/shared 21개 파일은 0.16.0 원본과 바이트 단위로 동일합니다. 서버의 장비·배치·구매 허용 규칙을 변경하지 않았습니다.

원본 증거: [하단 창 측정 JSON](screenshots/equipment-dock/metrics.json), [장비 검사 결과](screenshots/equipment-dock/equipment-results.json), [하단 창 안내](DOCK_TABS.md), [장비 드래그 안내](EQUIPMENT_DRAG.md). 이전 설명은 `SCREEN_QA_0.16.0.md`에 보존했습니다.

## 재실행

```sh
npm ci
npm run build
npm run setup:browser
npm test
npm run test:dock-tabs:browser
npm run test:equipment:browser
npm run test:rewards:browser
npm run test:screen-mode:browser
npm run test:swap:browser
npm run test:history:browser
npm run test:results:browser
```

`test:pc-dock:browser`와 `test:mobile-dock:browser`는 공통 검사의 해당 모드만 실행합니다. 공통 검사 포트는 2612, 장비 검사 포트는 2614입니다. 동일한 검사를 동시에 실행하지 마세요. Chromium 설치와 `CHROME_PATH` 설정은 [SCREEN_QA_0.13.3.md](SCREEN_QA_0.13.3.md)를 참고하세요. 게임 실행에는 브라우저 검사용 도구가 필요하지 않습니다.

게임 실행은 `npm ci` → `npm start`입니다. `npm start`는 현재 소스를 먼저 빌드합니다. 개발 서버는 `npm run dev`로 실행합니다. 하단 화면 모드 선택 줄에서 실제 빌드 버전 **v0.17.0**을 확인할 수 있습니다.
