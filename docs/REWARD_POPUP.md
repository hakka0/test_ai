# 0.13.1 라운드 보상 팝업

## 적용 범위

기준은 최종 결과 화면이 포함된 0.12.0입니다. 전장 크기, PC 오른쪽 패널, 페이지 스크롤, 대기석/상점 전환, 기록/기여도와 최종 결과 배치는 그 버전을 사용합니다. 보상 선택 후보를 전장 위 팝업으로 옮기고 눈 버튼/닫기/다시 열기만 추가했습니다. 수령 내역과 등급 확률은 원래 보상 위치에 남습니다.

## 조작

보상 라운드의 준비 시작에 골드/유닛/아이템 세 후보 팝업을 자동 표시합니다. 전장으로 화면을 이동한 뒤 전장을 중심으로 팝업 위치를 계산하고 화면 안으로 조정합니다. 작은 화면에서는 팝업 본문 내부를 스크롤합니다.

오른쪽 아래 눈 버튼을 누르는 동안 본문과 배경이 투명해집니다. 버튼은 남으며 놓으면 복원됩니다. 키보드는 눈 버튼에서 Space/Enter를 누르고 있는 동안 동일합니다. 회전·화면 크기 변경·앱 전환·포커스 이탈·터치 취소·두 번째 손가락 입력 시 복원됩니다. 투명 상태는 조회만 가능하며 배경 배치/상점 조작은 차단합니다.

닫기/Escape는 팝업만 닫습니다. 반복 상태 갱신으로 자동 재열리지 않으며 전장 상단의 **라운드 보상 보기**로 돌아옵니다. 배치나 제작이 필요하면 닫고 원래 화면에서 조작한 뒤 다시 보상을 열 수 있습니다. 새로고침/재접속 시 미선택 보상은 다시 표시합니다.

보상 선택이 완료되면 팝업과 다시 열기 버튼이 사라집니다. 닫기/눈 버튼은 후보 추첨·수령 상태·골드·시간에 영향을 주지 않습니다. 준비 시간은 계속 흐르며 준비 완료/마감에 미선택 골드를 자동 지급합니다. 후보/수령/제작의 기존 서버 규칙은 `REWARDS_CRAFTING.md`를 보세요.

## 수동 확인과 자동 검사

0.13.3에서 Chromium의 팝업/눈 버튼 마우스·터치·키보드, 크기 변경 시 복원, 닫기/재열기/재접속, 후보 선택/제작/자동 지급 검사를 통과했습니다. 팝업·투명 조회 스크린샷도 확인했습니다. 아래 항목은 실제 기기에서 추가 확인할 수 있습니다.

- PC에서 원래 전장 크기·오른쪽 관리 패널·대기석/상점·기록/최종 결과 배치를 확인합니다.
- `npm run dev:debug` → 혼자 연습하기 → 개발 디버깅 → 보상 프리셋으로 세 후보를 확인합니다.
- 전장 위 팝업 위치, 작은 화면의 내부 스크롤, 눈 버튼 누르기/놓기/회전/앱 전환/Space/Enter를 확인합니다.
- 닫기→전장 배치/드래그 자리 교환→상단 보상 다시 열기와 준비 완료/마감 자동 골드 지급을 확인합니다.
- 후보 선택 후 재열기 버튼이 사라지는지, 새로고침/재접속/개발 복원으로 미선택 보상이 정상 표시되는지 확인합니다.

`npm run build` → `npm run setup:browser` → `npm run test:reward-popup:browser`로 실행합니다. 임시 서버 포트는 2582이며 기존 브라우저를 쓰려면 `CHROME_PATH`를 지정합니다. 실행 결과와 제한은 `VALIDATION.md`에 있습니다.
