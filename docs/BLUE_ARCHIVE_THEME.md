# 블루 아카이브 팬게임 테마 (v0.24.0)

비공식 2차 창작 게임이라는 정체성을 화면 전체에서 알아볼 수 있게 한 테마입니다. 원작의 로고·워드마크·공식 UI 에셋은 사용하지 않았고, 하늘색·남색·노란 강조라는 색 체계와 사선 모양만 따랐습니다. 헤더의 고리+마름모 표식은 CSS로 그린 일반 엠블럼입니다.

## 파일 구성

- `client/ba-theme.css`: 이번 테마 레이어. 토큰(`--ba-*`)과 모양 규칙이 모두 여기에 있습니다. `interface-theme.css` 뒤에 불러오며 선택자에 `html:root body`를 붙여 이전 규칙보다 우선합니다.
- `client/interface-theme.css`: 기존 회녹색 계열 색을 하늘색 계열로 옮겼습니다. 색조 165~235° 전체와 채도가 낮은 회녹색(120~165°)만 이동했고, 승리 초록·패배 빨강·금·보라·조합 단계색 같은 의미색은 그대로입니다.
- `client/board.ts`: Phaser 전장의 타일·이름표·체력바 색. 내 유닛은 파랑(`0x2aa8f0`), 상대는 분홍빨강(`0xf0607c`)입니다.
- `client/main.ts`: 헤더 표식·문구, 로비 문구와 캐릭터 6명, 푸터의 비공식 팬 2차 창작 안내.

## 디자인 규칙

| 항목 | 값 |
| --- | --- |
| 기본 파랑 | `--ba-blue` #1b9cf2, 진한 파랑 `--ba-blue-deep` #0b6fc2 |
| 글자(남색) | `--ba-navy` #12294d |
| 테두리 | `--ba-line` #a7cee9 |
| 진행 버튼(노랑) | `--ba-yellow` #ffd23f. 준비 완료·혼자 연습하기·다시 플레이·조합 제작에만 사용 |
| 패널 모양 | 대각선 모서리 둥글기 `--ba-cut`, 위쪽에 파란 3px 선(안쪽 그림자라 크기가 바뀌지 않음) |
| 제목 | 이탤릭, 왼쪽에 사선 막대 |

노란색은 "진행"만 뜻하게 아껴 쓰고, 나머지 강조는 파랑으로 통일합니다. 조합 단계(브론즈·실버·골드)와 속성색은 의미색이라 바꾸지 않았습니다.

## 가독성 보정

순위표 태그(6~10px → 9~10px), 순위표 Lv(11px → 12px), 대기석 이름(10px → 11px)을 키웠습니다. 상세 능력치 라벨(11px)은 좁은 칸에서 넘칠 수 있어 그대로 두었습니다.

## 색을 바꾸는 방법

- 전체 분위기: `ba-theme.css` 맨 위 `:root` 토큰만 바꿉니다.
- 전장: `board.ts`의 `0x…` 색상 값. DOM과 Phaser 색이 따로라서 함께 바꿔야 합니다.
- 기존 규칙의 개별 색: `interface-theme.css`는 색 값이 그대로 들어 있습니다(변수화는 후속 과제).

## 확인하지 못한 것

이 작업 환경에서는 패키지를 설치할 수 없어 Vite 빌드, `npm test`, 브라우저 자동 검사를 실행하지 못했습니다. 아래는 정적 미리보기(헤드리스 Chrome)로만 확인했습니다.

- 로비 PC 1400 폭과 모바일 390 폭.
- 게임 화면은 `main.ts`의 실제 마크업과 직접 만든 샘플 카드로 만든 PC 1400×1000 근사 화면입니다. 실제 Phaser 전장과 `pc-layout.ts`의 배치는 포함하지 않습니다.

따라서 모바일 세로·가로 게임 화면, 1024×768, 실제 전투 중 화면은 직접 확인이 필요합니다. 모바일 가로는 겹침 위험을 줄이려 사선 모서리·상단 파란 선을 적용하지 않고(`:not(.landscape-layout)`) 색 이동만 적용했습니다. 확인 명령: `npm ci && npm test && CHROME_PATH=/usr/bin/google-chrome npm run test:pages:browser`.

## 손대지 않은 개선 후보

상점 카드(약 108px)와 대기석 줄(약 52px)의 크기 불균형, 유닛 상세의 길이, `style.css`(3,000줄)와 `interface-theme.css`의 중복 정리는 레이아웃을 바꾸는 작업이라 실제 화면을 보며 하는 편이 안전해서 남겨 두었습니다.

## 상점 창 (v0.24.0)

카드 바깥 크기(108px, 그리드 행 고정)는 그대로 두고 카드 안쪽만 바꿨습니다. 규칙은 `ba-theme.css` 맨 아래, 이미지는 `public/ui/shop/`(코인·특성 엠블럼 3종·자물쇠·카드 배경 SVG, 모두 이번에 직접 그린 일반 도형)에 있습니다.

| 항목 | 변경 |
| --- | --- |
| 가격 | 카드 하단 전체 폭 노란 띠, 코인 아이콘 + 16px 굵은 숫자 |
| 글자 | 이름 14px(사선 흰 라벨), 특성 12px(엠블럼 + 이름). 모바일 가로는 엠블럼만 남기고 숨기지 않음 |
| 색에만 의존하지 않기 | 레어도 `★n` 숫자 배지, 합성 가능 시 초록 "합성" 깃발, 골드 부족 시 자물쇠 + "골드 부족" 글자(aria-label에도 추가) |
| 조작 | 리롤·경험치 구매 버튼 최소 높이 44px, 기존 그리드 위치 유지. 리롤은 파란 버튼 + 코인 |

`main.ts`는 카드에 `data-unaffordable`, `.shop-rarity`, `.shop-merge-ribbon`, `.shop-lack` 요소를 추가했을 뿐 기존 선택자·속성(`data-offer`, `data-merge-ready`, `.shop-price` 숫자, `.shop-portrait img`)은 그대로입니다.

확인하지 못한 것: 이번에도 빌드·테스트를 실행하지 못했고(네트워크 차단), PC 1400 폭과 1024 폭 정적 미리보기만 봤습니다. 모바일 세로·가로 카드와 `tests/reference-dock.browser.cjs`의 가격 글자 크기 단언(`priceFont`)은 직접 확인이 필요합니다. 글자 크기 100/125/150% 설정은 아직 넣지 않았습니다.
